# TA-DPFL: paper-aligned implementation bundle

> **Privacy accountant correction (2026-11-02):** This bundle corrects a factor-of-two error in the previous release's Poisson-sampled Gaussian RDP formula for `0 < q < 1`. Do not use epsilon values, calibrated noise, checkpoints or results generated by an earlier bundle. Read `ACCOUNTANT_FIX_NOTICE.md`, rerun tests, recalibrate noise and rerun all DP experiments from scratch.

This project is a runnable research prototype based on the uploaded paper, **“Typology-Aware Privacy Scheduling for Differentially Private Federated AML Transaction Detection.”** It implements the paper's primary transaction-level formulation: simulated bank clients, a transaction-local MLP, FedAvg, typology-stratified Poisson sampling, per-example clipping, Gaussian noise, per-record RDP accounting, and typology-specific evaluation.

## Important scope boundary

The paper's motivation discusses transaction graphs and cross-institutional structure, but its primary privacy-constrained method deliberately excludes graph message passing, account identifiers, neighbourhood aggregates and graph-history features. This code follows that primary formulation. It is **not** a GNN, does not reconstruct cross-client graph structure, and does not claim account-level, node-level, whole-graph or laundering-attempt-level privacy.

The privacy unit is one transaction under add/remove adjacency. The transaction includes its features, label and fixed typology metadata. The typology assignment process itself is not protected. The implementation assumes one owner per transaction and a predeclared public institution roster.

## What is included

- Dataset loading, exclusive strata, timestamp splits and fixed transaction-local feature hashing.
- A public typology exposure schedule with largest-remainder step allocation.
- Independent Poisson sampling for the focus stratum and background stratum.
- Per-example global L2 clipping and one Gaussian perturbation to the combined clipped sum.
- Fixed public normalization; no division by the realized batch size.
- Integer-order Poisson-sampled Gaussian RDP accounting and noise calibration for Policy U and Policy D.
- A validation comparison against Opacus' RDP implementation. Formal privacy output is blocked when required independent validation is unavailable or fails.
- Central NN, capped-row GBDT, FedAvg, uniform-DP-FL, an individualized-DP-SGD-style comparator, TA-DPFL Policy U and TA-DPFL Policy D comparisons.
- Overall AP/ROC-AUC/precision/recall/F1/FPR, typology-specific AP, threshold selection on validation data, logs, checkpoints and report template.
- Unit tests for preprocessing, scheduling, sampling, clipping and accountant behaviour.

## What is not included or supplied

1. The research paper does not provide the benchmark files. You must obtain the IBM AML-Data HI-Small dataset separately.
2. The paper reports typology-annotated positives, but the commonly distributed HI-Small transaction CSV may not include those annotations. This project will **not invent typology labels**. Provide a separate, documented annotation file or a typology column that genuinely accompanies your benchmark.
3. The paper does not give numerical values for relevance scores, privacy targets, sampling rates, clipping, normalization, learning rate, architecture or training duration. The YAML includes clearly labelled engineering examples for some fields and leaves the privacy targets/relevance scores unset. Set them before running private experiments.
4. This is a single-machine simulation. It is not a production deployment across banks.
5. The implementation's numerical optimizer finds a feasible noise schedule and attempts an SLSQP variance reduction, but it does not certify global optimality. The generated report says this explicitly.

## 1. Install

Use Python 3.10 or 3.11 in a clean virtual environment. Install a PyTorch build appropriate for your CPU/GPU from the official PyTorch installation selector, then install the remaining requirements:

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Opacus is required for the independent accountant comparison. The runner always requires OS-backed secure randomness. With `require_opacus_validation: true` (the default), it stops unless the independent Opacus comparison passes. Setting that flag false is only for exploratory code-path testing; reports will mark `formal_privacy_claim_permitted: false` if the independent check is unavailable or fails. Do not disable the check merely to obtain a privacy number.

## 2. Prepare the dataset and typology annotations

- Put the original HI-Small CSV at `data/HI-Small_Trans.csv` (or edit `data.path`).
- Confirm the column names in `configs/experiment.yaml`. Standard benchmark field names are configured by default.
- Supply typology annotations as `data/typology_annotations.csv` with exactly the required fields `source_row_id,typology`, or point the config to the genuine typology column in the raw file.
- `source_row_id` is the zero-based row position in the **unchanged original CSV**. Keep the original file and row order intact. The template file `data/typology_annotations_template.csv` is only a header/template, not actual annotations.
- Valid positive typologies are CYCLE, GATHER-SCATTER, BIPARTITE, FAN-OUT, SCATTER-GATHER, STACK, RANDOM and FAN-IN. Positive transactions with no supplied label are UNCL. Every non-laundering transaction is BG. An unannotated positive is never converted into BG.
- If genuine typology annotations are unavailable, you can set `allow_all_uncl: true` for a pipeline diagnostic, but this does not implement or test typology-aware scheduling in the scientific sense.

See `data/README.md` for details.

## 3. Freeze split cutoffs and client roster

Run the preprocessing audit:

```bash
python run_experiment.py --audit-only
```

This writes:

- `outputs/data_audit.json`
- `outputs/public_client_ids_candidate.json`

Review the UTC timestamp cutoffs in `outputs/data_audit.json` and copy them into `data.train_end_timestamp` and `data.validation_end_timestamp` in the YAML configuration. Copy the approved fixed public institution roster into `data.public_client_ids` as a YAML list of strings. These constants are held fixed for the neighbouring-dataset privacy analysis; do not recompute them separately for different privacy runs.

Split semantics are train when timestamp is before the first cutoff, validation from the first cutoff up to (but not including) the second cutoff, and test at or after the second cutoff. Repeated timestamps stay together, so realized split percentages may differ slightly from exactly 60/20/20. The audit reports actual counts.

Example structure (replace these strings with the audit's real UTC cutoffs and roster):

```yaml
data:
  train_end_timestamp: "<UTC timestamp from audit>"
  validation_end_timestamp: "<UTC timestamp from audit>"
  public_client_ids:
    - "<public client id 1>"
    - "<public client id 2>"
```

The participating institutions are treated as a public, fixed roster. If the roster itself is confidential or derived from the presence of protected transaction records, this implementation's privacy assumptions need to be revisited.

## 4. Complete the privacy configuration

In `configs/experiment.yaml`, set:

- `epsilon_uniform`
- `epsilon_min`
- `epsilon_max`
- `relevance_scores` for **all nine** positive groups (eight typologies plus UNCL)

Choose and document these values with the responsible AML/privacy reviewers before looking at validation or test results. The relevance score is a public training-priority policy, not a probability of criminality. The policy must not be estimated from private group counts or test outcomes.

The YAML also provides example values for `lambda_exploration`, `eta`, `q_focus`, `q_background`, `q_uniform`, `clip_norm`, `normalization` (the paper's fixed B0), number of rounds and local steps. These are implementation choices, **not numbers provided by the paper**. Review them for the experiment. The total number of local optimizer steps per client must give every positive stratum at least one focus step; the scheduler rejects a zero-step stratum.

Regime A (matched maximum privacy cap) requires relevance scores normalized so their maximum is 1 and `epsilon_max == epsilon_uniform`. The program computes actual worst-case record bounds and writes `outputs/privacy_comparison.json`. If the bounds do not match within `privacy_matching_tolerance`, report a privacy-utility frontier, not a strictly matched comparison.

### Individualized-DP-SGD-style comparator

The paper names an individualized-DP-SGD-style baseline without fully specifying its sampling/noise-placement algorithm. To avoid silently claiming an exact reproduction, this bundle makes the operationalization explicit: all strata are mixed and Poisson-sampled at the same `q_uniform` on every local step; each sampled transaction's clipped gradient receives an independent Gaussian noise vector using the noise multiplier calibrated to that transaction's fixed stratum target; those noisy per-record contributions are summed before the fixed `B0` normalization. There is no typology-focused exposure schedule. The comparator uses the Policy-D target profile (including the BG target). Its report is labelled as an operationalization, not as the exact method in references [34]/[35].

```bash
pytest -q
```

The Opacus comparison test is skipped when Opacus is unavailable. A full DP experiment with `require_opacus_validation: true` will stop instead of reporting unvalidated privacy values.

## 6. Run experiments

After the dataset, annotation source, timestamp cutoffs, public client roster and privacy configuration have been reviewed and frozen:

```bash
python run_experiment.py
```

The first run is intentionally modest and should be treated as a pilot. For a study, use multiple independent seeds, sufficient local steps, relevance-score controls (uniform, inverted and shuffled), and confidence intervals. Generate ablation configurations with `python -m experiments.make_relevance_controls --config configs/experiment.yaml`; review each generated config and run it separately. The run settings are fixed by the YAML configuration.

## 7. Privacy and scientific interpretation

- Per-example gradients are clipped globally across all trainable parameters.
- The focus and BG Poisson samples are combined before clipping-sum aggregation; one Gaussian noise tensor is added to the combined clipped sum.
- `B0` is fixed and public. The realized sampled batch size is never used as the divisor.
- Empty batches still produce a noise-only optimizer update.
- Every local optimizer step across all communication rounds is included in record-level accounting.
- A focus-stratum record accrues privacy cost only at steps focused on its stratum. BG records accrue cost at every step.
- Uniform weights are used in FedAvg. Raw records and unprotected individual gradients are not sent to the coordinator.
- The reported global epsilon is the maximum record-level epsilon across positive strata and BG, not an average.
- Validation threshold selection uses disjoint validation data; that does not provide a privacy guarantee for validation records themselves.
- The mechanism assumes cryptographically sourced randomness for Poisson sampling and Gaussian noise when `secure_randomness: true`. Do not turn it off for a formal DP claim.
- A record-level guarantee for one transaction does not automatically provide useful protection for a multi-transaction laundering attempt; the paper's group-privacy bound may be weak for large groups.
- The benchmark is synthetic and cannot establish performance on confidential production bank data.

## 8. One-day execution reality

A one-day outcome depends heavily on whether the raw benchmark, genuine typology annotations, public client roster, frozen split cutoffs, Python environment and hardware are already available. On a CPU, manual per-example gradient computation over millions of rows may not finish within one day. Reduce the run to an explicitly labelled pilot if necessary; do not silently change the privacy accountant or sampling method to make it faster.

## Citation basis

The implementation follows the uploaded paper's primary formulation and experimental plan: sections III–V, including exclusive strata, predeclared schedule, Poisson sampling, per-example clipping, Gaussian perturbation, per-record RDP accounting, Policy U/Policy D and typology-specific AP. The paper itself leaves key numerical settings and parts of the experimental section as placeholders; this bundle does not invent them as source facts.
